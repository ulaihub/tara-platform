## Résumé

Depuis la PR #39, la vérification du code de connexion échouait sur le serveur (apps et back-office), ainsi que l'écran « Équipe et audit ». Cause : `tara update` ne reconstruisait pas l'outil de migration (service du profil « outils », ignoré par `docker compose build`). Il gardait le code du jour de l'installation et n'appliquait aucune nouvelle migration ; l'API lisait des colonnes absentes de la table des comptes.

- **Mise à jour du serveur** : l'outil de migration est reconstruit à chaque `tara update`, puis la dernière migration du code doit figurer dans la base ; sinon la mise à jour s'arrête avant de redémarrer l'API. Après la récupération du code, `tara update` relance sa nouvelle version, pour qu'une correction de la procédure s'applique tout de suite.
- **Rôles** : ouvrir une boutique ou devenir livreur réécrivait les rôles du compte à partir de ceux de la session, qui n'incluent pas les rôles de l'équipe sans second facteur : un administrateur testant une app avec son numéro perdait son rôle. Le rôle est maintenant ajouté en une seule écriture, sans toucher aux autres.
- **Données de départ** : rejouées à chaque mise à jour, elles remettaient le compte administrateur à « client + administrateur » ; le rôle administrateur est désormais garanti sans retirer les autres.
