# PR 22 · CI allégée : un workflow par partie, APK seulement à la fusion

## Pourquoi

Le dépôt est privé sur un compte GitHub gratuit : minutes d'Actions et stockage des artefacts limités chaque mois. Le quota est atteint (vérifications de la #21 bloquées par la facturation). Une modification consommait environ 42 minutes, dont environ 23 pour construire les APK des deux apps à chaque push.

## Ce qui change

- Un workflow par partie, lancé seulement quand ses fichiers changent :
  - `ci.yml` : API, back-office, page de suivi (ignoré si seules les apps Flutter changent ; les styles de carte restent surveillés car le back-office les importe) ;
  - `rider.yml` : app livreur et paquets partagés ;
  - `client.yml` : app expéditeur et paquets partagés ;
  - `map-preview.yml` : aperçus quand un style de carte change ;
  - `secrets.yml` : recherche de secrets à chaque modification.
- Dans une PR, les apps sont testées (format, analyse, tests, captures) sans construire les APK. APK, contrôle du poids et symboles : à la fusion sur `main` ou sur demande (`workflow_dispatch`), gardés 14 jours.
- Groupes de concurrence par workflow, pour qu'ils ne s'annulent pas entre eux.
- Dependabot : une fois par mois au lieu d'une fois par semaine.
- `docs/ARCHITECTURE.md` : décision 37.

Les jobs sont copiés tels quels depuis l'ancien `ci.yml`, avec seulement la condition `if: github.event_name != 'pull_request'` sur les étapes APK.

Estimation : environ 7 minutes pour une modification du seul back-office, au lieu d'environ 42.
