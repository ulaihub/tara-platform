# PR 41 · Connexion : le refus du code reste affiché, lecture du SMS limitée aux SMS de Tara

Fusionnée le 2026-11-16 · branche `connexion/erreur-code-visible`

## Résumé

Quand le serveur refusait le code de connexion (faux, expiré, trop d'essais, numéro bloqué pour la journée), l'app affichait le message puis vidait les cases, ce qui effaçait aussitôt le message : l'écran semblait repartir de zéro, et la lecture automatique du SMS donnait l'impression de tourner en rond.

- **Apps expéditeur et livreur** : le message de refus reste affiché jusqu'à ce que l'utilisateur retape un chiffre.
- **Lecture automatique du SMS** : seuls les SMS de Tara sont retenus ; un autre SMS à 6 chiffres (Mobile Money, opérateur) ne fait plus perdre un essai.
- **Serveur** : `tara connexions [numéro]` montre les derniers codes demandés, les codes faux et le blocage d'un numéro ; `tara debloquer numéro` lève le blocage (10 codes faux en 24 h), fait expirer les codes en cours et l'inscrit au journal d'audit.

## Vérifications

- Parcours de connexion rejoué sur une base neuve (demande du code avec l'empreinte de l'app, vérification, conditions, création du compte) : conforme côté serveur.
- Nouveau test dans chaque app : code refusé, cases vidées, message visible, pas de nouvel essai automatique ; il échoue sur l'ancienne version de l'écran.
- App expéditeur : analyse, 339 tests ; app livreur : analyse, 476 tests ; paquet `tara_sms` : 3 tests.
- Requêtes de `tara connexions` et `tara debloquer` exécutées sur une base locale (numéros masqués, entrée au journal d'audit).
