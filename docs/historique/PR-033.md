# PR 33 · Notifications de l'app expéditeur (Android et iPhone)

Fusionnée le 2026-11-15 · branche `notifications/expediteur`

## Résumé

Le serveur envoyait déjà aux expéditeurs les notifications de leurs commandes : livreur trouvé, colis récupéré, livré, livraison impossible, point placé par le destinataire, réponse du support. L'app expéditeur, elle, n'était pas enregistrée dans Firebase et ne recevait rien.

- **App expéditeur** :
  - Firebase est initialisé au démarrage. Les options Android de `cm.tara.app` (app enregistrée dans le projet tara-ulaihub) sont dans `firebase_options.dart` ; celles de l'iPhone sont données à la construction.
  - Le jeton est enregistré depuis l'accueil (`PUT /me/devices/:id/push-token`). Le serveur l'efface déjà à la déconnexion.
- **Notification touchée** : elle ouvre le suivi de sa commande, que l'app soit en arrière-plan ou fermée. `PushService.opened` et `takeInitialOpened` sont dans `tara_core`, partagés entre les deux apps.
- **Android, les deux apps** : petite icône des notifications (silhouette du logo) au lieu du carré blanc.
- **iPhone** :
  - droit `aps-environment` et mode `remote-notification` pour l'app expéditeur ;
  - variables Firebase iOS distinctes par app dans `codemagic.yaml` et `docs/IOS.md` (`FIREBASE_IOS_RIDER_*`, `FIREBASE_IOS_CLIENT_*`).
- **`PushService`** : un jeton APNs en retard ne bloque plus le démarrage.
